# Domain Docs

## Before exploring

Read root `GLOSSARY.md` and the ADRs in `docs/adr/` relevant to the work.

If these files are absent, proceed silently. `/domain-modeling` creates them lazily when terminology or decisions are resolved.

## Layout

This is a single-context repository: one root `GLOSSARY.md` and shared `docs/adr/`.

## Vocabulary and decisions

Use glossary terms consistently in tickets, proposals, and code discussions.
If a needed concept is missing, reconsider the term or note the gap for `/domain-modeling`.
If a proposal contradicts an existing ADR, identify the ADR and explain why the decision should be reopened.
